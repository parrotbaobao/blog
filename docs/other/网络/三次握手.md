### 三次握手干了什么

1、客户端发起 SYN 报文段
2、服务器收到后，回应 SYN+ACK 报文
3、客户端收到后，发送 ACK 给服务器

以上只在 TCP 层进行，也就是传输层，握手完之后再进行下一步（应用层传到传输层）

#### 顺序逻辑
浏览器准备 HTTP 数据（应用层）
交给 TCP 层前，TCP 检查：
连接是否建立？
如果没有建立 → 发起三次握手
三次握手完成 → TCP 连接就绪
浏览器把 HTTP 报文交给 TCP
TCP 才会继续向下层封装并发送

### 三次握手发生了什么

具体场景（浏览器访问网页）
场景：浏览器访问 https://example.com/index.html
浏览器准备数据（应用层）
浏览器想发送 HTTP 请求
HTTP 还没发，因为 TCP 连接没建立
三次握手开始（传输层）
第一次握手：客户端发 SYN → IP/数据链路/物理层封装发送
第二次握手：服务器收到 SYN → TCP 层生成 SYN+ACK → IP/链路层封装返回
第三次握手：客户端收到 SYN+ACK → TCP 层生成 ACK → IP/链路层封装发送
握手完成
TCP 连接建立
浏览器才会把 HTTP 请求交给 TCP 层 → 再走 TCP/IP 分层发送
